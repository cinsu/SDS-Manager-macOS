# v0.0.8h — Export to Scanner can add and remove Favorites Lists (REAL SCANNER WRITE, pending physical test)

Builds on v0.0.8g (create list inside Add to Favorites, deletion). Export to Scanner now supports:
- **New lists:** a new `favorites_lists/f_NNNNNN.hpd` plus its one new row in `f_list.cfg`.
- **Removed lists:** only lists deleted in THIS program whose file on the scanner is still byte-identical to the
  archived copy made at deletion time (SHA-256). A deletion is marked spent after a successful export.
- Both can be combined with edits to existing lists in one export.

Safety rules (all enforced before anything is written):
- New list files must be complete, conventional-only, correct column counts, valid frequencies/modulation/service
  type, no duplicate department quick keys. New trunked lists are still refused.
- `f_list.cfg` may only gain rows for the lists being added and lose rows for the lists being removed; every other
  row, header line and line ending must be unchanged; new rows must not take a quick key / number tag already used.
- Scanner-only lists unknown to the local configuration (or edited on the scanner since deletion) are never removed;
  the export is blocked with an explanation instead.
- A new list never reuses the filename of a deletion that has not yet been exported.
- Order: new files, edited files, `f_list.cfg`, then removals, so an interruption can leave an unreferenced file but
  never an index row pointing at a missing file. Fresh verified backup first; failure restores every changed file
  (new files deleted, edited/removed files restored from the backup).
- The export preview shows **REMOVE FROM SCANNER** separately from **RETAIN ON SCANNER**.

Tests: test_list_sync_export.py (isolated mock scanner built from real SDS100 files). See NEW_LIST_EXPORT_TEST.md
for the physical test. Not yet verified on hardware.
